# 서비스 속도 개선

> 2026-06-06

## 배운 것

**응답시간**
1. 앱에서 API 요청
2. SQL 실행, 응답 생성 등
3. API 응답

**처리량**
- TPS(transaction per second): 초당 트랜잭션 수
- RPS(request per second): 초당 요청 수

**성능 개선 방법**: 서버 동시 요청 수 늘리기, 처리 시간 줄이기

**TPS 높이는 법**
- 처리시간이 오래 걸리는 작업 식별(모니터링 도구 사용. 주로 DB, 외부 API 연동 과정)

**수직 확장**: CPU, 메모리, 디스크 등 자원을 증가
- 즉각적인 효과
- 비용이 많이 듬

**수평 확장**: 서버 추가 투입
- DB, 외부 API 성능이 문제일 시 효과 X

**로드 밸런서**: 사용자 트래픽을 여러 대의 서버에 골고루 분배, 트래픽 조절
정적 방식
- 라운드 로빈: 클라이언트 요청을 각 서버에 순차적 분배
- IP 해시: 클라이언트 IP 주소를 해시한 값을 기반으로 요청 서버 결정
동적 방식: 서버의 현재 상태(연결 수, 응답 시간 등)에 따라 트래픽을 분산. 트래픽이 적은 서버에 요청

**DB 커넥션 풀**
요청 마다 DB에 연결, 종료 -> 커넥션(연결)을 미리 생성해 풀에 보관, 사용
커넥션 풀 크기, 커넥션 대기 시간, 커넥션의 유지 시간을 설정해야함

최대 유휴 시간: 커넥션을 풀에 유지할 수 있는 최대 시간
유효성 검사: 커넥션이 정상적으로 사용할 수 있는지 확인
최대 유지 시간: 커넥션이 생성된 후 유지되는 시간
